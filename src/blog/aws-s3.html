01 — Introducción

¿Qué es Amazon S3?

Amazon Simple Storage Service (S3) es el servicio de almacenamiento de objetos de AWS. Permite guardar cualquier tipo de archivo —imágenes, videos, backups, código, logs— con alta disponibilidad y durabilidad (99.999999999%).

A diferencia de un sistema de archivos tradicional, S3 trabaja con objetos dentro de buckets. Cada objeto tiene una clave única (nombre), el contenido y sus metadatos.

Casos de uso comunes

Almacenar imágenes subidas por usuarios, servir assets estáticos, guardar backups de bases de datos, alojar sitios web estáticos e integrar con otras APIs de AWS.

02 — Conceptos

Conceptos clave

  • Bucket: contenedor principal de S3. Su nombre debe ser único a nivel global en AWS.
  • Objeto: cualquier archivo almacenado en S3 (hasta 5 TB por objeto).
  • Clave (Key): identificador único del objeto dentro del bucket (funciona como ruta).
  • ACL: lista de control de acceso para definir permisos sobre buckets y objetos.
  • Bucket Policy: política JSON para controlar accesos a nivel de bucket.
  • Versioning: guarda múltiples versiones de un mismo objeto.
  • Lifecycle rules: reglas automáticas para mover o eliminar objetos según su antigüedad.
03 — Práctica

Crear un bucket desde la consola

  1. Ve a AWS Console → S3 → Create bucket.
  2. Ingresa un nombre único global (ej. hannia-dev-assets-2026). Los nombres no pueden tener mayúsculas.
  3. Selecciona la región más cercana a tus usuarios (ej. us-east-1).
  4. Por defecto S3 bloquea el acceso público. Déjalo así si los archivos son privados.
  5. Activa Versioning si necesitas historial de cambios en los archivos.
  6. Haz clic en Create bucket.
⚠ Nombres únicos globales

El nombre del bucket debe ser único en todo AWS, no solo en tu cuenta. Si el nombre ya existe, tendrás que elegir otro.

04 — AWS CLI

Operaciones con AWS CLI

Primero instala y configura la CLI:

Instalación y configuración
# Instalar AWS CLI (Ubuntu)
sudo apt install -y awscli

# Configurar credenciales
aws configure
# Te pedirá: AWS Access Key ID, Secret Key, región y formato de salida

Subir archivos

Upload
# Subir un archivo
aws s3 cp foto.jpg s3://mi-bucket/images/foto.jpg

# Subir una carpeta completa (recursivo)
aws s3 cp ./dist/ s3://mi-bucket/app/ --recursive

# Sincronizar carpeta local con el bucket
aws s3 sync ./build s3://mi-bucket --delete

Listar y descargar

Listar / Descargar / Eliminar
# Listar contenido del bucket
aws s3 ls s3://mi-bucket/

# Descargar un archivo
aws s3 cp s3://mi-bucket/foto.jpg ./descarga/foto.jpg

# Eliminar un objeto
aws s3 rm s3://mi-bucket/foto.jpg

# Eliminar todos los objetos de una carpeta
aws s3 rm s3://mi-bucket/temp/ --recursive
05 — Seguridad

Permisos y políticas

Para hacer que un objeto sea público (ej. una imagen en tu web), primero debes desactivar el bloqueo de acceso público en el bucket y luego aplicar una política:

Bucket Policy — lectura pública
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::mi-bucket/*"
    }
  ]
}
⚠ Cuidado

Solo haz pública la información que realmente deba ser pública. Nunca pongas credenciales, configs o datos sensibles en un bucket público.

06 — Caso de uso

Alojar un sitio web estático

S3 puede servir archivos HTML/CSS/JS como un sitio web sin necesidad de un servidor:

  1. Crea el bucket con el nombre de tu dominio (ej. hannia.dev).
  2. Ve a Properties → Static website hosting → Enable.
  3. Define el Index document como index.html y el Error document como error.html.
  4. Aplica la bucket policy de lectura pública del paso anterior.
  5. Sube tu proyecto con aws s3 sync.
💡 Tip

Para SSL y dominio personalizado, combina S3 con CloudFront (CDN de AWS) y Route 53 (DNS).

07 — Buenas prácticas

Buenas prácticas

  • Activa el versionado en buckets que contengan archivos importantes para evitar pérdidas accidentales.
  • Usa IAM roles en lugar de access keys directamente para acceder a S3 desde EC2.
  • Configura lifecycle rules para mover archivos viejos a S3 Glacier y reducir costos.
  • Habilita el cifrado en reposo (SSE-S3 o SSE-KMS) para datos sensibles.
  • Activa S3 Access Logs para auditar quién accede a tus archivos.
  • Nunca expongas claves de acceso en código público (usa variables de entorno o IAM roles).
