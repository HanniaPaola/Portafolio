01 — Introducción

¿Qué es AWS Lambda?

AWS Lambda es un servicio de cómputo serverless. Significa que puedes ejecutar código sin provisionar ni administrar servidores. Solo pagas por el tiempo de ejecución real de tu función, medido en milisegundos.

Lambda escala automáticamente: si tu función recibe 1 o 10,000 invocaciones simultáneas, AWS lo maneja por ti. Es ideal para tareas event-driven, webhooks, procesamiento de archivos y backends ligeros.

Capa gratuita

Lambda ofrece 1 millón de invocaciones gratuitas por mes y 400,000 GB-segundos de cómputo. Es más que suficiente para proyectos personales y pruebas.

02 — Conceptos

Conceptos clave

  • Handler: función de entrada que Lambda ejecuta. Recibe el evento y el contexto.
  • Event: objeto JSON con los datos del trigger (request HTTP, archivo subido, etc.).
  • Context: información sobre la ejecución (tiempo restante, ID de la invocación).
  • Trigger: servicio que invoca la función (API Gateway, S3, CloudWatch, etc.).
  • Layers: dependencias compartidas entre funciones (como node_modules).
  • Timeout: tiempo máximo de ejecución (máx. 15 minutos).
  • Memory: RAM asignada (128 MB a 10 GB). Más memoria = más CPU también.

03 — Práctica

Tu primera función Lambda

Vamos a crear una función simple con Node.js desde la consola de AWS:

  1. Ve a AWS Console → Lambda → Create function.
  2. Selecciona Author from scratch.
  3. Asigna un nombre: mi-primera-lambda.
  4. Elige el runtime: Node.js 20.x.
  5. En Permissions, deja el rol por defecto (crea uno nuevo).
  6. Haz clic en Create function.

Código del handler

Una vez creada, edita el código en el editor inline:

index.mjs — Node.js 20
export const handler = async (event, context) => {
  // Loguear el evento recibido
  console.log('Evento recibido:', JSON.stringify(event, null, 2));

  const nombre = event.queryStringParameters?.nombre ?? 'mundo';

  return {
    statusCode: 200,
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      mensaje: `¡Hola, ${nombre}!`,
      timestamp: new Date().toISOString()
    })
  };
};

Probar la función

Evento de prueba (JSON)
{
  "queryStringParameters": {
    "nombre": "Hannia"
  }
}

Haz clic en Test y verás la respuesta en la sección Execution results.

💡 Deploy

Después de editar el código, siempre haz clic en Deploy para guardar los cambios. Sin ese paso, las modificaciones no surten efecto.

05 — API Gateway

Lambda + API Gateway

La combinación más común es exponer Lambda como un endpoint HTTP usando API Gateway:

  1. En tu función Lambda, ve a Add trigger.
  2. Selecciona API Gateway → Create a new API → HTTP API.
  3. Elige Open para pruebas (en producción usa autenticación).
  4. Copia la URL generada y pruébala en tu navegador o con curl.
Probar el endpoint con curl
curl "https://abc123.execute-api.us-east-1.amazonaws.com/default/mi-primera-lambda?nombre=Hannia"

# Respuesta esperada:
# {"mensaje":"¡Hola, Hannia!","timestamp":"2026-01-15T10:30:00.000Z"}

Variables de entorno

Configura variables de entorno para no exponer datos sensibles en el código:

Acceso en Node.js
// Lambda → Configuration → Environment variables
// Agrega: DB_HOST, DB_PASSWORD, API_KEY, etc.

export const handler = async (event) => {
  const dbHost = process.env.DB_HOST;
  const apiKey = process.env.API_KEY;
  // Usa las variables sin exponerlas en el código
};
06 — Integración

Lambda + S3: procesar archivos al subirlos

Un caso muy común es ejecutar una función Lambda automáticamente cuando se sube un archivo a S3 (ej. generar thumbnail de una imagen):

  1. En tu función, ve a Add trigger → S3.
  2. Selecciona el bucket y el tipo de evento: PUT (al subir un archivo).
  3. Opcionalmente filtra por prefijo o sufijo (ej. solo archivos .jpg).
Handler — trigger de S3
import { S3Client, GetObjectCommand } from '@aws-sdk/client-s3';

const s3 = new S3Client({ region: 'us-east-1' });

export const handler = async (event) => {
  // Obtener info del archivo subido
  const bucket = event.Records[0].s3.bucket.name;
  const key = event.Records[0].s3.object.key;
  const size = event.Records[0].s3.object.size;

  console.log(`Archivo subido: ${key} (${size} bytes) en ${bucket}`);

  // Aquí puedes: redimensionar imagen, parsear CSV, enviar notificación, etc.

  return { statusCode: 200, body: 'Procesado exitosamente' };
};
⚠ Permisos IAM

El rol de ejecución de tu Lambda necesita permisos s3:GetObject en el bucket de origen para poder leer los archivos. Agrégalos en IAM → Roles.

07 — Buenas prácticas

Buenas prácticas

  • Mantén las funciones pequeñas y con responsabilidad única. Una Lambda = una tarea.
  • Configura el timeout adecuado. El valor por defecto es 3 segundos; auméntalo si tu función hace operaciones de red.
  • Usa variables de entorno para cualquier valor que pueda cambiar entre entornos (dev, staging, prod).
  • Activa CloudWatch Logs para debuguear tus funciones. Todo lo que imprimas con console.log aparece ahí.
  • Evita cold starts pesados: no inicialices conexiones de BD dentro del handler, hazlo fuera para reutilizarlas.
  • Configura Dead Letter Queues (DLQ) para capturar invocaciones fallidas y no perder eventos.
💡 Resumen

Lambda es una herramienta poderosa para construir backends event-driven sin administrar servidores. Combinado con API Gateway, S3 y DynamoDB forma la base de muchas arquitecturas serverless modernas en AWS.
